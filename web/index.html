Cortex Documentation

A developer-friendly guide to setting up persistent codebase memory and context compaction for AI coding assistants.

What is Cortex?

Cortex is an open-source local tool that runs on your computer and acts as a smart brain and memory cache for your AI coding agents (like Cursor, Claude Desktop, and Cline).

Normally, when you ask an AI coding assistant to work on a file in a large project:

  • It dumps 10 to 30 whole files into the prompt (40,000+ tokens), which wastes money, hits token limits, and makes the AI slower.
  • It forgets your rules: In a new chat session, it repeats mistakes (e.g. using the wrong database driver or forgetting your custom component rules).

Cortex solves this by creating two simple local structures inside your repository:

  1. .project-cortex.json: A map of your code symbols, functions, and imports.
  2. .cortex/ledger/: A log of architectural rules, decisions, and bug warnings that never causes Git merge conflicts.

2-Minute Quickstart

Get Cortex running in your project in under 2 minutes:

1. Run init in your project directory

TERMINAL 
# Run in your repository root
npx cortex-graph init

2. Add to Cursor or Claude Desktop

Paste this into your .cursor/mcp.json or Claude Desktop config:

JSON 
{
  "mcpServers": {
    "cortex": {
      "command": "npx",
      "args": ["-y", "cortex-graph", "mcp"]
    }
  }
}

3. Ask your AI agent to pull context

Now when working on a file, your agent automatically calls Cortex to get a tiny 1,200-token context slice instead of reading 20 files!

How It Works (Plain English)

Cortex operates in three simple steps:

1. Code Mapping

Cortex scans your TypeScript, JavaScript, Python, Dart, and Rust files. It maps which classes, functions, and interfaces talk to each other.

2. Decision Memory

Whenever you make a major architectural decision (e.g. "Use Redis for session revocation"), Cortex logs it to .cortex/ledger/. You can attach a test command (e.g. npm test auth.test.ts). If the test passes, the decision is locked in as a verified rule.

3. Token Slicing

When the AI needs context for TokenService, Cortex only fetches:

  • The exact interface signatures of TokenService and its direct callers.
  • Active rules & invariants attached to TokenService.
  • Known bug warnings (gotchas).

Everything else is stripped away, reducing 48,000 tokens of raw file text down to 1,200 tokens.

CLI Command Reference

You can run Cortex commands directly from your terminal:

Command What it does Example
cortex init Scans your code and sets up local Cortex files. cortex init
cortex context Prints the sub-2.5k token summary for a file or function. cortex context src/auth/token.ts
cortex decision Saves an architectural rule or decision into memory. cortex decision "Use Redis for tokens" --target "src/auth"
cortex sync Re-scans files you edited and updates the code map. cortex sync
cortex blast Shows everything that could break if you edit a file. cortex blast src/auth/token.ts

Cursor & Claude Desktop MCP Tools

When Cortex runs as an MCP server, it exposes these tools to your AI agent:

Tool Name Parameters Description
cortex_get_context targetSymbol (string) Returns the compacted 1.2k token slice for the target symbol.
cortex_record_decision title, targetNode, invariants Saves a new rule or decision into the repository memory ledger.
cortex_blast_radius targetSymbol Returns direct callers and affected test suites for a function.
cortex_sync None Refreshes the AST code map after you make code changes.

TypeScript Programmatic SDK

Use Cortex in custom Node.js/TypeScript automation scripts or custom agent frameworks:

TYPESCRIPT 
import { CortexEngine, CompactorEngine } from 'cortex-graph';

// Initialize Cortex engine
const cortex = new CortexEngine(process.cwd());
await cortex.initialize();

// Extract compacted context slice
const compactor = new CompactorEngine(cortex);
const slice = await compactor.compact({
  targetSymbol: 'src/auth/token.service.ts::TokenService'
});

console.log('Token count:', slice.tokenCount); // e.g. 1,180 tokens
console.log('Invariants:', slice.invariants);
